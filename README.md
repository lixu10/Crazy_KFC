# KFC大学选课程序

##  这是什么

事情要从一个普普通通的周四说起。

那天下午，室友在宿舍群里甩了一张照片：两枚金黄酥脆、还冒着热气的葡式蛋挞，旁边大剌剌印着「**5 块钱，2 个**」。配文一行大字——「刚抢的，香疯了，楼下还剩最后 20 份，手慢无。」

我当时正对着作业发呆，瞳孔猛地一缩。

**5 块钱。两个。蛋挞。**

你算算，一个蛋挞折合两块五。食堂的蛋挞六块钱一个，还干得像砖头。这哪里是蛋挞，这是经济学，是缘分，是我命里该有的那口酥脆。

我抓起手机冲进肯德基，指尖在屏幕上划出火星子。已售罄。刷新。已售罄。再刷。……三分钟后，最后 20 份变成 0 份，而我的晚饭还是一包泡面。

那晚我躺在床上翻来覆去，想的不是作业，是那两枚蛋挞。**5 块钱 2 个蛋挞，错过一次就少一次**，人生能遇上几回这种好事？我痛定思痛，得出了一个改变命运的结论：

> 抢蛋挞，拼的不是手速，是**耐心**——耐心到愿意写一个替我等、替我看、替我出手的程序。

于是这个项目诞生了。它干的事其实特别朴素：

- 我睡觉、上课、写作业的时候，它**替我一直守着**；
- 蛋挞一补货，它**第一时间喊我**，一封邮件直接呼到我脸上（喊 → 邮件提醒）；
- 真到了上架的瞬间，它**出手比任何人类都快**，抢到就收手，绝不恋战；
- 它也比我更懂「稳」字怎么写：动手之前先把方案核对清楚，绝不给你留下「旧的没了、新的也没了」这种惨剧；
- 就算后台把我挤下线了，它也能**自己悄悄爬回来继续站岗**。

后来，我把这套「蹲守 → 提醒 → 出击 → 收尾」的打法整理成一个网页控制台：界面干净，想自己独享就双击跑在本机，想喊上宿舍一起守还能部署到服务器上各自登录。至于它蹲的到底是哪家店、哪张券……

实话实说：**哪家店不重要。** 重要的是——只要你想守候的是那个东西，它都能替你守候，然后在最合适的瞬间替你出手。

> 你也许可以用这个程序抢别的东西，但是这与项目作者设计的初衷不一样哦~

## 功能

| 模式 | 说明 |
|------|------|
| **抢课** | 持续查询目标余量，出现空位时自动提交选课，成功后移出队列，全部完成即结束 |
| **仅监控** | 只轮询余量变动，出现余量时通知（首次出现 + 重新满员后再次出现才再次通知），**不执行任何选课** |
| **安全改选** | 先把“退掉的旧课 → 要选的新课”一一配对；检测到目标有余量时自动完成 退课 → 选课，失败自动回退选回原课；写请求结果不确定时以“已选列表”对账为准，绝不留下“退了旧课没选上新课” |

其它能力：

- **自动发现选课批次**：登录时自动捕获并验证批次 ID；未命中时按“上次成功 → 兼容候选”继续尝试，仍失败可手动粘贴批次 ID 验证后采用。
- **Token 过期自动重登**：运行中会话失效时用内存中的密码自动重新登录并继续；连自动重登都失败才停在页面等你重新输入密码。
- **设置界面可改**：学生班级（决定容量口径）、轮询间隔、HTTPS 证书校验开关、SMTP 邮箱均可改并保存，重启后仍然生效。
- **邮件通知**：选课/改选成功、发现余量、改选回退、需人工处理等场景异步发送。
- **运行状态一目了然**：顶部显示 认证 / 批次 / 任务 三个状态灯，下方有任务阶段、每个目标的容量与状态、以及一条可滚动的事件时间线。

## 启动

### 方式一：双击 `start.bat`（推荐）

首次运行会自动创建 `.venv` 虚拟环境并安装依赖，之后每次双击直接启动并打开浏览器。

### 方式二：命令行

```bash
# Windows
python -m pip install -r requirements.txt
python main.py

# 或先建虚拟环境再运行
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python main.py
```

启动后保持终端窗口打开（它同时是日志出口），关闭窗口或按 `Ctrl+C` 退出；退出时会尽量安全停止正在运行的任务。

## 使用方法

1. **登录**：用自己的统一认证学号与密码登录（多用户部署时每人各自一个账号）。密码只保存在程序当前进程的内存里，不会被写入磁盘或回传到页面。**每个学号同一时间只允许一个活动会话**：已在别处登录时会提示“请先退出”。
2. **批次**：登录成功后一般会自动取得“选课批次”。若未取得，可点“重新发现批次”，或在左侧切到“手动指定”粘贴 32 位批次 ID 后点“验证并采用”。（批次 ID 可在选课页地址栏 `batchId=` 后看到。）
3. **搜索加入目标**：选择课程类型，输入**完整课程名或课程代码**（精确匹配），勾选需要的教学班“加入目标队列”。
4. **选模式并启动**：
   - **抢课 / 仅监控**：目标队列即任务目标，直接启动。
   - **安全改选**：先点“加载当前已选课程”，在左侧“要退掉的旧课”里勾选与目标队列**数量相同**的课程（按顺序一一对应），再点“用队列目标建立改选对”，核对后启动。
5. 运行中可用“停止任务”协作式停止；抢课/改选会在安全的边界停下来，不会中途丢操作。

> 同一时间只运行一个任务。任务运行期间，用于“准备下一轮”的控件会被锁定——它们改的是下一次任务的快照，不影响当前正在跑的任务。

## 配置说明（页面上角“设置”）

| 项目 | 含义 |
|------|------|
| 学生班级 | 用于判断某课程对你是否属于“内部容量”，可留空（按外部容量口径） |
| 轮询间隔 | 每次查询的基础间隔秒数（最小 1 秒）；每次会自动叠加 ±0.5 秒随机抖动，避免请求节奏过于规律 |
| 关闭证书校验 | 仅当所在网络存在代理/中间证书导致 SSL 报错时才勾选；默认开启校验更安全 |
| 网络代理 | 仅当访问统一认证/选课系统需要走代理时才开。地址可带 `用户名:密码`，支持“启用/停用”，凭据只保存在你自己的账号设置文件中，页面与 API 不回传密码。会**自动忽略服务器环境变量里的全局代理** |
| 邮件通知(SMTP) | 开关、安全方式(SSL/STARTTLS)、服务器、端口、账号、授权码、收件人 |

QQ 邮箱授权码获取：QQ 邮箱 → 设置 → 账户 → 开启 POP3/SMTP → 生成授权码。授权码与代理凭据都按账号保存在 `data/users/<学号>/settings.json`，该目录已被 `.gitignore` 排除、不会入库；页面和 API 也**不会回传**明文，只显示“是否已配置 / 脱敏地址”。收不到或想清掉旧授权码，可用“发送测试邮件”和“清除已保存授权码”按钮。

## 部署到服务器（Docker Compose）

同一份程序，既能当**单机本地工具**（`start.bat` / `main.py`），也能部署到服务器，让**多名同学各自用自己的统一认证账号**登录使用（设置、SMTP、网络代理都按账号分开）。

### 快速开始

```bash
# 1) 准备访问口令（可选：不设 = 完全开放，公网请务必设置）
echo "ACCESS_TOKEN=换成你的访问口令" > .env

# 2) 构建并启动（单容器，暴露 8642 端口）
docker compose up -d --build
docker compose logs -f web
```

打开 `http://服务器IP:8642/`：若设了口令会先弹一次“访问口令”，之后每个用户用自己的统一认证学号登录即可，互不干扰。

### 可选环境变量

| 变量 | 作用 |
|------|------|
| `ACCESS_TOKEN` | 设置后所有页面与 API 都先要求该口令（浏览器保存 30 天）；留空 = 完全开放 |
| `COOKIE_SECURE` | 反向代理已开 HTTPS 时设 `1`，让登录 Cookie 带 Secure 标记 |
| `SID_MAX_AGE` | 登录 Cookie 有效期秒数，默认 `2592000`（30 天） |
| `BIND_HOST` / `PORT` | 监听地址与端口，默认 `0.0.0.0:8642` |

### 单进程约束（务必遵守）

登录会话、后台任务和自动重登要用的内存密码都只存在于**单个进程**里，因此本服务必须**单进程运行**（进程内多线程即可并发服务多用户）。默认入口 `waitress`（Dockerfile 中 `CMD python serve.py`）正是单进程多线程；**不要**改成 gunicorn 多 worker —— 每个 worker 各自持有状态，会互相“顶掉”会话、任务也会重复执行。由此推论：

- **重启即全员掉线**：`docker compose restart` 或更新镜像会清空全部内存会话，所有用户需重新登录；正在跑的任务会被安全停止。
- 各账号设置都持久化在 `data` 卷（`kfc_data`），重启不丢；丢的只是“登录状态 + 运行中的任务”。

### 建议加一层反向代理（HTTPS）

```nginx
server {
    listen 443 ssl;
    server_name 你的域名;
    # ssl_certificate / ssl_certificate_key ...;
    location / {
        proxy_pass http://127.0.0.1:8642;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

并给容器加 `COOKIE_SECURE: "1"`。

### 数据与迁移

账号设置（SMTP 授权码、代理凭据等）存放在 `data/users/<学号>/settings.json`（容器内即 `kfc_data` 卷）。旧版单用户 `data/settings.json` 会在某个账号首次登录时自动迁移一份过去，原文件保留不动。该目录已同时被 `.gitignore` 与 `.dockerignore` 排除，不会进镜像或仓库。

## 安全说明

- 单机使用（`start.bat` / `main.py`）时只监听 `127.0.0.1`、不做 CORS、不对外网卡开放。
- **服务器部署时按上文监听 `0.0.0.0`**，此时请务必设 `ACCESS_TOKEN` 访问口令，并建议放在反向代理（HTTPS）后面；每位用户都用自己的统一认证账号，互不访问他人会话。
- 统一认证**密码**、token、Cookie、`secretVal` 一律不落盘、不写日志、不回传浏览器（多用户下也只存在于各自登录进程的内存里）。
- SMTP 授权码、代理地址与密码按账号选择持久化在 `data/users/<学号>/settings.json`（已 `.gitignore`）；页面与 API 只回传“是否已配置 / 脱敏地址”。
- 网络代理**只认账号自己设置的代理**，会自动忽略服务器环境变量里的全局代理，避免服务器全局代理把某位用户的请求带偏。
- 日志中的敏感字段会被自动打码（密码、token、授权码、代理凭据都在内）。
- 旧命令行版本的 `route`、`jsessionid`、`action.log` 文件新版本不再读取或生成，可自行删除（已加入 `.gitignore`）。

## 项目结构

```
├── main.py               # 单机启动器：挑空闲端口、开浏览器、退出时停任务
├── start.bat             # 单机一键启动（首次自动建环境装依赖）
├── serve.py              # 服务器入口：waitress 单进程多线程（默认 0.0.0.0:8642）
├── wsgi.py               # WSGI 入口（供其它单进程 WSGI 服务器加载）
├── Dockerfile            # 服务器镜像
├── docker-compose.yml    # docker compose 编排（含可选 ACCESS_TOKEN）
├── .dockerignore
├── requirements.txt
├── kfc_college/          # 应用包
│   ├── __init__.py       #   Flask 应用工厂（会话绑定 + 可选访问口令 + Cookie）
│   ├── sessions.py       #   多用户会话：每账号一登录会话、每用户独立设置
│   ├── config.py         #   配置读写、日志与脱敏
│   ├── client.py         #   统一认证登录 + 选课接口（每账号内存会话，支持每用户代理）
│   ├── courses.py        #   容量口径、搜索、规范化
│   ├── tasks.py          #   任务管理：抢课 / 监控 / 安全改选状态机
│   ├── notifier.py       #   SMTP 邮件通知
│   ├── models.py         #   领域模型
│   └── web.py            #   页面与 JSON API
├── templates/index.html  # 界面结构
├── static/app.css        # 界面样式
├── static/app.js         # 界面逻辑（短轮询任务状态与事件）
├── data/settings.json    # 运行后生成：旧版单用户设置（某账号首登时自动迁移）
├── data/users/<学号>/settings.json  # 运行后生成：各账号设置（授权码、代理等）
└── logs/app.log          # 运行后生成：轮转日志
```
